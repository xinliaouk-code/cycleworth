# CycleWorth V4：iPhone 使用与 Apple Watch 自动同步报告

更新日期：2026-10-17。发布结果与验证边界见本文末尾。

## 这次改了什么

首页从整条模块长页改成四个主要目的地：

| 默认入口 | 内容与用途 |
|---|---|
| 概览 | 累计骑行、里程、省钱与热量；当天骑行建议；同步入口 |
| 骑行 | 搜索、筛选和排序记录；查看路线、速度、爬升；调整通勤/日常交通/休闲分类；通勤识别规则 |
| 爱车 | 购车/装备成本、回本进度、成就与自行车保养 |
| 趋势 | 按周骑行分布和距离/省钱趋势 |

设置 → 底部导航：四个下拉框对应从左到右的位置。可从概览、骑行、爱车、趋势、同步、设置中选择；选择已固定的项会交换位置，始终保持四个不同入口。登录后保存到账号；未登录时只保存在当前设备。未固定的页面可通过「全部功能」或设置中的功能列表打开。原有模块隐藏与排序仍由布局设置控制。

iPhone 页面包含底部安全区留白、至少 44px 的主要触控区域、16px 表单文字和主屏幕应用元数据。底栏固定在屏幕下方，内容预留空间。Safari 打开 https://cycleworth.vercel.app/dashboard ，用分享菜单「添加到主屏幕」；如果系统显示「作为网页 App 打开」，保持开启。首次从主屏幕进入时可能需要重新登录。它仍需要网络，不承诺离线浏览或后台读取健康数据。

## 数据流与新账号

Apple Watch 记录体能训练 → 同步至 iPhone 的 Apple 健康 → Health Auto Export 读取获授权的数据 → HTTPS POST 到 CycleWorth → 校验、去重、分类 → Neon 保存 → 网页展示。

网站不会直接连接 Apple Watch，也不能替代 iPhone 的健康权限弹窗。新正式库按你的授权从空库启用；旧 Supabase 未恢复、未删除、未迁入。需要在新系统注册/验证邮箱并登录。旧账号密码不能假定自动有效。后续迁移需要按邮箱与应用身份核对新旧用户及已有骑行，不能直接盲导以免冲突。

## 一次性配置：建议按照这个顺序

1. 在手表用「体能训练」记录骑行；结束后等它完整出现在 iPhone「健身」或「健康」。户外骑行需要地图时，先确认原始记录已经有路线。
2. 安装并打开 Health Auto Export。你已有付费版，仍请确认当前购买项已解锁 Automations / REST API。界面名称可能随版本/语言变化。开放所需运动、路线、骑行距离、能量等读取权限；不必为了 CycleWorth 上传睡眠等无关数据。
3. 在 CycleWorth 注册或登录并完成邮箱验证码验证，进入「设置 → Apple Health Sync」。点击「生成同步凭证」。它是专用上传密钥，不是登录密码，只显示一次。
4. 在同一 iPhone 点击「在 Health Auto Export 中配置」。网站会通过官方 App URL scheme 预填自动化。每点一次都会创建一条，所以不要反复点；保留一条 CycleWorth 自动化即可。链接含密钥，不要分享。
5. 初次配置使用 Dry Run 预览。保持手机解锁，在导出 App 的 Manual Export 中选择一条完整骑行所在日期并发送。回到 CycleWorth 点刷新，看新增、失败、跳过等结果。
6. 确认预览正常后，在 CycleWorth 点「开启新增骑行写入」。回到导出 App 的同一条自动化，将 `X-CycleWorth-Dry-Run` 改为 `false`。再次发送，确认「骑行」页出现记录。
7. 用同一批数据再发一次，预期显示「已存在」，总里程和记录数不增加。到这一步才完成设备到网站的首次验收。

快捷配置基于 [HealthyApps 官方 Deep Link 文档](https://help.healthyapps.dev/en/health-auto-export/automations/deep-link/)。网页已实现链接生成与参数测试；在你的真实 iPhone 上打开 App、授权和发送仍需你完成。

## 手动配置表（快捷打开失效时使用）

以下是本项目选择的默认配置，不是实时同步承诺。

| 项目 | 填写值 |
|---|---|
| Automation Type | REST API |
| Name | CycleWorth Cycling |
| URL | `https://cycleworth.vercel.app/api/health/sync` |
| Method | POST |
| Data Type | Workouts |
| Workout 类型 | 在 App 中筛选 Cycling；预填链接未限定类型，后端也会跳过非骑行 |
| Export Format / Version | JSON / V2 |
| Include Route Data | 开启 |
| Include Workout Metrics | 开启，时间分组 Minutes |
| Date Range | Default：昨天和今天，便于重试昨日未成功导出的记录 |
| Sync Cadence | 1 hour |
| Batch Requests | 开启 |
| Request Timeout | 120 seconds |
| Header 1 名称 | `Authorization` |
| Header 1 值 | `Bearer ` 后加本次生成的完整凭证，保留中间空格 |
| Header 2 名称 | `X-CycleWorth-Dry-Run` |
| Header 2 值 | 首次 `true`；开启写入后改 `false` |
| 通知 | 首次验收期间开启 Notify When Run，稳定后可自行关闭 |

JSON 的 Content-Type 由导出 App 设置。配置界面的入口与选项以 [官方 REST API 指南](https://help.healthyapps.dev/en/health-auto-export/automations/rest-api/) 为准。

## 尽量自动化的日常办法

日常保留上述每小时尝试同步，iPhone 允许 Health Auto Export 后台 App 刷新和网络连接。网站无需常驻。健康数据在锁屏时不可读，iOS 也会限制后台运行，低电量等状态可能延迟执行；设置了每小时不等于整点一定执行。

建议加一个可手动补跑的快捷指令：在「快捷指令」新增，搜索 Auto Export，选择 **Run Automation**，指定 CycleWorth Cycling。先手动跑通，再建立每天常用解锁时段的个人自动化，例如晚间回家后；用确认后运行，收到提示后解锁执行。也可放在主屏幕，漏同步时点一下。不要用固定锁屏时间任务来承诺无人值守读取健康数据。[官方快捷指令配置说明](https://help.healthyapps.dev/en/health-auto-export/automations/schedule-automations-using-shortcuts/)

我的方案采用重复时间窗口与服务端去重：偶发失败后重跑同一天的数据，无需自己判断哪些已经传过。若隔了多天没同步，用手动日期范围补齐，再恢复日常窗口。

## 历史补录、保存字段与边界

两种导入路径已经实现：

- 导出 App 直接发送：Manual Export 选历史日期，使用相同 URL 和凭证。按天开始，确认成功后分段补齐。
- 手动 JSON：先在 App 导出 Workouts JSON V2，再到 CycleWorth「同步 → 手动导入 JSON」上传，先预览，再在页面确认新增。

每个请求上限 4 MiB、100 条运动；单条路线最多 50,000 个 GPS 点。遇到超限先缩小日期范围并开启分批。如果单次骑行本身已超限，缩小日期范围无效，需要另行处理该条文件；不会悄悄删减路线点来冒充完整导入。

保存日期、时长、距离、起终点、GPS 路线、可用的平均/最高速度、累计爬升、热量与高程轮廓。平均速度缺失但距离/时长可用时可计算；最高速度、爬升等缺失时不编造。路线存在至少两个有效点才显示地图。室内骑行无户外轨迹。心率、踏频、功率、睡眠目前没有分析页面，不能因为导出文件包含这些字段就认为 CycleWorth 已保存和展示它们。格式依据 [官方 Workout V2 字段说明](https://help.healthyapps.dev/en/health-auto-export/export-format/workouts/)。

同一个 Workout ID 重传只返回已存在，不重复累计，也不覆盖已有手动分类。相似的跨来源记录会暂缓新增，返回待复核。当前没有批量自动合并待复核记录的界面。**已导入记录暂不自动补齐后来才到达的路线/指标**；首次正式导入前请确认手机上的记录完整，缺失记录需要另行核对处理。这也是预览步骤存在的原因。

通勤识别使用已保存的站点与 London 时区时段；请先配置你的住处/工作附近站点与时间，再点「保存当前通勤规则供同步使用」。默认站点只是初始配置。没有可用 GPS 或未命中规则的记录，请在骑行页检查并手动分类。省钱金额取决于分类与票价规则，不等于 Apple Watch 本身提供的数值。

Apple Health 历史补录不能还原旧系统的手动标签、养护记录或其它自定义设置。这部分仍需之后单独迁移旧库。

## 怎么判断成功、怎么排错

真正成功的证据是：导出 App 日志请求成功，CycleWorth 最近请求更新，结果为「写入」，骑行页出现预期日期/距离，重复发送后记录数不变。只有「已配置」、HTTP 200 或预览新增计数，都不足以单独证明骑行已保存。

| 现象 | 检查与处理 |
|---|---|
| 完全没有请求 | 手机解锁、网络、后台刷新、健康读取授权；查看自动化 Activity Logs |
| 401 | Authorization 内容错误或凭证已撤销；轮换后更新导出 App |
| 403 | 写入开关未开、dry-run 不正确，或历史导入缺少页面确认 |
| 413 | 缩小请求/日期范围并开启分批；确认是否单条路线本身过大 |
| 429 | 等至少 60 秒再重试 |
| 503 / 超时 | 稍后重跑同一批；不要新建多个相同自动化来重试 |
| HTTP 207 | 部分记录失败，检查结果中失败项；成功条目重发仍可去重 |
| 没有新骑行但返回成功 | 看是否 Dry Run、已存在、非骑行跳过或待复核 |
| 地图没路线 | 先核对 Apple 健身里的原始路线与授权；已导入缺失路线不会自动补齐 |
| 有路线但底图空白 | 检查地图瓦片网络；路线数据与地图底图是两个独立部分 |

凭证可在网站撤销或轮换；旧凭证会立即失效。服务器保存哈希，网页只在生成时展示明文；不要把它发到聊天、截图或仓库。新库与旧库独立，未授权的其它 Supabase 项目没有访问。
